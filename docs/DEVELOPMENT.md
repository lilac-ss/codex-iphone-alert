# 開発・テスト・導入手順

この文書は準備段階の手順です。
まだ実装していないコマンドを、実行可能なものとして記載しないでください。

## 開発

1. `PLAN.md` と `HANDOFF.md` を読み、現行Codexデスクトップのイベント連携を確認します。
2. 動作対象のNode.jsバージョンを決め、プロジェクトで明示します。ユーザーのグローバル環境を無断で更新しません。
3. Mac用処理、静的PWA、テストの最小構成を作ります。
4. npmなどのパッケージ管理方法を統一し、依存とロックファイルを保存します。
5. package.jsonに開発・テスト・公開用ビルドのコマンドを定義し、この文書とREADMEを更新します。

Mac用コード、Webアプリ、テストはそれぞれ所在を明確にします。
必要以上にフレームワークやサービスを増やしません。
Web Pushの暗号処理はライブラリを使います。

## 自動テスト

時刻、Macの前面アプリ・ロック状態、Push送信を差し替えられるようにします。
外部ネットワーク、実機、実際の購読情報なしで、通知制御を検証できることを条件にします。

計画書の自動テスト項目に加え、次を確認します。

- 不正な購読データを受け付けず、任意URLへの送信やシェル評価を行わない。
- 導入を複数回実行しても既存通知を二重登録しない。
- 既存設定に追加した箇所を識別でき、他の設定を壊さず解除できる。
- 公開用ディレクトリへ秘密情報・端末登録情報・Macの設定をコピーしない。

テスト結果には実行コマンドと成功・失敗を記録します。
未実装の段階では「テスト成功」と記載しません。

## 公開前

1. テストを完了し、Pagesへ配信する静的ファイルを確定します。
2. 秘密鍵、端末登録情報、個人設定、実イベントの内容が含まれていないことを確認します。
3. GitHub認証と配信先を確認します。
4. Pagesのリポジトリ配下URLでもmanifest・service worker・静的ファイルが動作するようにします。
5. HTTPSで公開し、URLと配信したコミットを記録します。

Macのローカル状態は公開物から分離します。
初回準備時点ではGitHubリポジトリを作成・公開していません。

## Macへの導入

1. 導入直前に現行のCodex設定を読み直します。
2. ユーザー用のリポジトリ外ディレクトリへ鍵・状態を保存します。
3. 既存のnotify・hooksをバックアップし、追加内容と復元方法を明示します。
4. 標準の信頼確認を経て通知hookを利用し、LaunchAgentを導入します。
5. CLIで状態を確認します。

個人設定のバックアップはMac内だけに置き、Gitには含めません。
アンインストールでは、このツールが追加した設定と起動項目を識別して除去します。
導入後にユーザーが変更した無関係な設定を古いバックアップで上書きしないようにします。

## iPhoneと実機検証

1. 公開URLをiPhoneで開き、ホーム画面へ追加します。
2. Webアプリのボタンから通知を許可し、端末登録情報をエクスポートします。
3. AirDropなどでMacへ渡し、CLIで取り込みます。
4. テスト通知、実際の完了・承認要求、1分後の再通知を確認します。
5. Macをロックした場合と、ロック解除後にCodexを前面にした場合を確認します。
6. 確認した端末・OS・条件・結果を記録します。

iPhoneを直接操作できない場合は、URLと短い操作手順をユーザーへ渡します。
ユーザーが確認していない実機結果を、完了として報告しません。
