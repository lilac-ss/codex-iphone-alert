その後、GitHub Pagesの配信、Macへの導入、iPhoneの初回登録、実機検証へ進めてください。

- ロックされていないMacでCodexを前面にすると停止
- 本文は固定文と時刻のみ
- 秘密鍵と端末登録情報はMac内のリポジトリ外に保存
- 初回登録はエクスポートとAirDropなどによるローカル取り込み
- 初版はiPhone側の停止操作や常設登録サーバーを設けない
- 既存のCodex通知を保持し、導入を取り消せるようにする

## 実装時に確認する点

### Codexイベント

`notify` は `agent-turn-complete` を扱います。
渡されるJSONには会話に由来する内容が含まれる可能性があります。
必要なイベント種別・内部識別子だけを扱い、payload全体を保存・ログ出力しないでください。

`PermissionRequest` が、現行デスクトップの自動承認審査と人間への承認要求のどの段階で発火するかを確認してください。
自動で処理される要求まで通知してしまう場合は、その限界と対応を明示してください。
動作を合わせる目的で承認方式を変更しないでください。

`Stop` hookは完了直前で発火し、処理が続く可能性があるため、確定計画の完了検知を無検証で置き換えないでください。

### Macの状態

前面化による停止はアプリ単位で、すべての保留イベントを対象とします。
個別タスクを読んだことまで証明する仕組みは不要です。
ロック状態の取得失敗を「ロック解除済み」と扱わず、実際のロック・復帰で検証してください。

### Web PushとPWA

Apple Web Pushではユーザーに見える通知を表示します。
通知を見せずに停止を伝えるsilent pushは使いません。
配送待ちの古い通知を抑えるTTLを検討し、採用値を文書化してください。
同じ通知tagによる再通知音の挙動は実機で確認してください。

購読情報の取り込みでは形式・HTTPS・Appleの正規Push送信先を検証し、任意のURLへ送信できないようにします。
最新の公式仕様を確認してから送信先制約を決めてください。
